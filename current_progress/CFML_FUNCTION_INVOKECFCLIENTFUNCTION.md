# Research: INVOKECFCLIENTFUNCTION — findings (2026-08-09)

## Summary: it is NOT a CFML function at all

`invokeCFClientFunction` is a **JavaScript** function generated by the ColdFusion **CFClient** framework (introduced in CF11 / "Splendor", part of the CF Mobile / PhoneGap client-side-CFML feature). It runs **in the browser**, not on the server. There is no server-side CFML builtin with this name.

Because the CFClient feature is **gone in ColdFusion 2025** (the `<cfclient>` tag is rejected outright, see below), the correct engine behavior when the identifier is used from server-side CFML is the runtime error the stub already reproduces. **Nothing needs to be implemented.**

## What it does (when the feature existed, CF11 → CF 2018)

- ColdFusion's CFClient compiler translated `<cfclient>` blocks (and CFML in files with `client="true"`) into JavaScript, emitting a `invokeCFClientFunction` helper alongside the translated functions.
- Device APIs (PhoneGap: `cfclient.camera.*`, etc.) and data APIs (`queryExecute`, `cfquery`) are inherently **asynchronous**. A `<cfclient>` UDF that (transitively, recursively) calls any such API is itself marked asynchronous by the CF compiler.
- Calling such an async UDF directly from hand-written JS does not work: the JS right after the call runs before the async chain finishes (the return value is `undefined`, and "Database created" prints *after* "After creating database"). This is exactly why `invokeCFClientFunction` exists — it wraps the call so the CF-generated callback chain completes first.
- Official docs (guides.adobe.com, still published 2026): *"ColdFusion automatically determines whether a function call is synchronous or asynchronous. However, if you need to invoke an asynchronous function in a synchronous mode, you can use the invokeCFClientFunction function... The invokeCFClientFunction function can be used to invoke both synchronous and asynchronous CFML functions from JavaScript."*
- Signature (Adobe docs): `invokeCFClientFunction(funcName, arg1, arg2, ..., successCallback)` — `funcName` (required), arbitrary args (optional), `successCallback` (mandatory; pass `null` if none). Ram Kulkarni's blog (engine's CFClient lead) confirms: first arg is the cfclient function name, followed by its args, last arg is the callback invoked after the async function completes.
- Added: ColdFusion 11. Example from the docs: `onclick="invokeCFClientFunction('createfile',null)"`.

## What ColdFusion 2025 actually does (byte-verified on RDS host 192.168.100.10)

1. `invokeCFClientFunction("myfunc","arg")` from server-side `<cfscript>` inside try/catch:
   - CF 2025 output: `start| ERR: Expression | Variable INVOKECFCLIENTFUNCTION is undefined. |end`
   - `WebStrada-cli` output: identical. The existing stub (`src/cffunctions/fn_ajax.cpp`) already matches CF byte-for-byte. ✔
2. `<cfclient>...</cfclient>` tag block:
   - CF 2025 → HTTP 500, parse-time error: **"Unknown tag: cfclient. ColdFusion cannot determine how to process the tag cfclient because the tag is unknown and is not in any imported tag libraries."**
   - The CFClient feature was deprecated; CF 2018 Update 16 disabled `cfclient` by default (security); by 2025 the tag is unknown.

## Conclusion / recommendation

- Keep the stub as-is: it reproduces the exact CF 2025 runtime error for a server-side reference, which is the only reachable path in this engine (no browser JS backend).
- `UNIMPLEMENTED_FUNCTIONS.md:21` and `PROGRESS.md:606` already document it correctly ("not a CF 2025 function").
- Do NOT attempt a real implementation (there is no server-side target to implement); the docs' `invokeCFClientFunction(func, args..., callback)` semantics belong to the removed client-side JS runtime.

## What INVOKECFCLIENTFUNCTION does at the low C level

Invokes a function on a client-side CFC proxy (uses a generated client stub).

- Arg 1: `component` (string).
- Arg 2: `method` (string).
- Arg 3: `argStruct` (struct).

## Parameter passing (by value / by reference)

Verified on Adobe ColdFusion 2025 (`RDS_HOST=192.168.100.10`): ColdFusion passes simple-value arguments (string, number, boolean) **by value** — mutating a parameter inside a function never changes the caller's variable. Structs and queries are passed by reference and arrays by value, but this function takes only simple arguments, so the caller's variables are always unchanged after a call.

- Arg 1: `component` (string). passed by value.
- Arg 2: `method` (string). passed by value.
- Arg 3: `argStruct` (struct). passed by value.

## Proposed compiled form

```cpp
cfvariant *cf_invokecfclientfunction(const cfvariant *a1, const cfvariant *a2, const cfvariant *a3);
```
Compiled as a direct JIT call (AGENTS.md rule), registered via `AddSymbol`; the compiler emits the call site with `3` argument(s) evaluated into `const cfvariant *` parameters.

## Dependency

Component/method invocation support; object serialization (Java-serialization-compatible); client stub generation.

## Ease of implementation

Low-to-medium: single-purpose call, no state to maintain, but needs the above library. Real (typed) implementation can be done in one function.
